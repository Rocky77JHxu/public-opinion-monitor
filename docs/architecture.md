# 架构设计

## 总体分层

系统分为采集层、原始数据层、处理层、结构化层与产出层。分层目标是隔离外部平台变化、保留审计证据、让规则与模型研判可追踪，并保证单平台失败不影响整体任务。

## 1. 采集层

采集层从三类来源生成原始条目：

- 热搜榜单。
- 通过 MediaCrawler 执行的关键词检索。
- 通过 MediaCrawler 执行的已授权账号检索。

采集器不负责业务评分。它的职责是：

- 发起受控请求。
- 保存原始响应或平台结果。
- 统一传输错误。
- 输出稳定的任务结果。
- 生成标准 `RawItem`。

## 2. 原始数据层

原始数据层保存不可变记录：

- 原始 JSON 或由 HTML 解析得到的结构化结果。
- 采集时间。
- 任务 ID 与采集器版本。
- 请求结果。
- 平台与来源元数据。

原始数据用于排查、审计与后续重放，必须设置有限保留周期。

## 3. 处理层

处理层负责：

- 字段规范化。
- 日期解析与时效过滤。
- URL 规范化与去重。
- 标题 / 内容相似度去重。
- 跨平台事件聚合。
- 规则分类。
- LLM 辅助分类。
- 地域实体提取。
- 评论证据获取。
- 评论情感分析。
- 多维度评分。

处理过程必须记录输入、规则版本、Prompt 版本、模型与输出置信度。

## 4. 结构化层

结构化层输出：

- 研判条目。
- 证据包。
- 分项得分。
- 综合得分。
- 预警级别。
- 风险理由。
- 建议动作。
- 不确定性说明。

## 5. 产出层

产出层将结构化事件转换为钉钉自动化 Payload，并负责：

- Payload 格式化。
- 投递策略。
- 重试与退避。
- 幂等控制。
- 投递状态记录。
- 失败告警。

## 运行原则

- 采集与处理解耦。
- 原始证据不可变。
- 每次转换记录版本与输入。
- 平台特有逻辑停留在平台适配器内。
- 业务规则来自配置与版本化 Prompt。
- 每条外发告警携带稳定事件 ID 与追踪 ID。
- 单平台失败只记录失败，不阻塞其他平台。
- 所有外部请求必须有超时、限流与最大重试次数。

## 目标拓扑

```text
调度器
  ├── 热搜采集器
  ├── MediaCrawler 关键词任务
  └── MediaCrawler 账号任务

原始数据存储
  ↓
清洗与去重
  ↓
增强与 LLM 分析
  ↓
评分
  ↓
结构化事件存储
  ↓
钉钉自动化产出
```
