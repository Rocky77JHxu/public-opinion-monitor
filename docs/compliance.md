# 合规与安全要求

本系统可能采集公开内容、账号信息、评论以及可间接识别行为的信息。生产部署前，部署方必须明确法律依据、采集目的、必要性与保障措施。

## 必须完成的审批

部署前应取得书面审查意见，覆盖：

- 适用网络安全法、个人信息保护法、数据安全法等法律要求。
- 平台服务条款。
- 采集目的、必要性与比例原则。
- 指定账号检索的授权依据。
- 数据保留期限。
- 访问控制。
- 是否涉及跨境存储或处理。
- 第三方依赖许可证。
- 政府或执法场景的特别限制。
- 数据主体权利保障流程。

## 采集控制

- 只采集配置范围内 的来源与字段。
- 避免不必要的完整主页或历史数据采集。
- 条目数与评论数必须有上限。
- 遵守间隔时间与浮动窗口。
- 每个平台设置并发上限。
- 不绕过认证、验证码或反滥用机制。
- 连续传输或认证失败时停止并报告。
- 不采集私信、非公开内容或未授权数据。

## 数据最小化

- 不推断未经授权的敏感属性。
- 输出中遮蔽手机号与身份证号。
- 评论分析优先输出聚合统计。
- 非必要不暴露无关自然人的身份标识。
- 原始 Payload 只保留排查与审计所需时长。
- 定期清理过期数据。

## 存储安全

- 数据库访问遵循最小权限。
- Webhook 与模型密钥使用环境变量或密钥管理系统。
- 不把生产密钥提交到 Git。
- 记录配置、证据与告警的访问审计。
- 开发与生产环境凭据隔离。
- 备份与恢复流程需要访问控制。

## 访问控制

- 按角色限制配置、原始数据、研判结果与投递记录访问。
- 高危操作要求二次确认。
- 导出数据需要审计记录。
- 定期复查账号权限。

## LLM 使用安全

- 不将不必要的个人数据发送给模型服务。
- Prompt 与模型输出版本化。
- 输出必须经过 Schema 校验。
- 保留不确定性与信息缺口。
- 禁止把模型结论当作已核实事实。
- 高级别预警必须有人工复核路径。

## 输出安全

- 未核实信息必须标记为“待核实”或“网传”。
- 输出来源、链接与采集时间。
- 输出不确定性说明。
- 避免系统自动直接决定处置动作。
- 同一事件不得重复推送。
- 投递失败必须可追踪并告警。
