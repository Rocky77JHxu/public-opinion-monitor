# MediaCrawler 集成设计

## 上游项目

上游仓库：

<https://github.com/NanmiCoder/MediaCrawler>

规划本地位置：

```text
third_party/MediaCrawler
```

不要把上游源码复制进业务模块。应将其隔离为可固定版本、可审计、可替换的第三方组件。

## 支持的平台标识

| 平台 | MediaCrawler 标识 |
|---|---|
| 小红书 | `xhs` |
| 抖音 | `dy` |
| 快手 | `ks` |
| bilibili | `bili` |
| 微博 | `wb` |
| 贴吧 | `tieba` |
| 知乎 | `zhihu` |

## 必需能力

- 关键词搜索。
- 指定创作者 / 账号采集。
- 详情采集。
- 评论抓取。
- JSONL 输出。
- 登录态复用。
- 受控休眠与请求频率。
- 可选连接已有 Chrome 实例的 CDP 模式。

## 集成边界

主系统职责：

1. 从 YAML 生成采集任务定义。
2. 写入任务记录。
3. 在隔离 Runner 中调用 MediaCrawler。
4. 读取 JSONL 输出。
5. 将平台记录映射为 `RawItem`。
6. 持久化任务结果与原始条目。

主系统不应依赖 MediaCrawler 私有内部实现；稳定的子进程与 JSONL 边界优先。

## 概念命令

```bash
uv run main.py --platform xhs --lt qrcode --type search
uv run main.py --platform dy --lt qrcode --type creator
```

实际命令必须由固定且审查过的配置生成，不允许任意用户输入直接拼接到命令行。

## 任务模型

每个任务应包含：

- 任务 ID。
- 平台。
- 采集类型：`search`、`creator`、`detail`。
- 关键词或账号配置。
- 最大条目数。
- 最大评论数。
- 超时时间。
- 输出目录。
- 登录态目录。
- 重试策略。
- 触发调度 ID。

## 运行要求

- 每个平台登录上下文默认最多同时运行一个任务。
- 使用保守的条目数与评论数。
- 浏览器登录态保存在 Git 外。
- 禁止记录 Cookie、密码或令牌。
- 任务 ID 与输出文件必须可互相关联。
- 超时后必须终止子进程与浏览器任务。
- 原始输出设置有限保留周期。
- 连续认证或传输失败时停止任务并告警。

## 结果加载

MediaCrawler 输出 JSONL 后，主系统需要：

1. 校验文件完整性与行数。
2. 逐行解析 JSON。
3. 根据平台映射字段。
4. 生成 `RawItem`。
5. 保存解析失败行与原因。
6. 记录任务成功率。
7. 不因单行失败丢弃整个文件。

## 许可证约束

MediaCrawler 上游项目声明面向非商业学习用途。政府或生产环境使用可能超出其许可证或平台条款范围。正式引入前必须完成：

- 法律审查。
- 平台条款审查。
- 使用范围审查。
- 必要授权获取。
- 替代方案评估。
